## ボスの自律的な移動

### 原因

旧移動の `roam` は床から360px上を中心とし、高さは役ごとに120〜176pxだった。中央の薄い足場は床から320px上にあるため、`roam` の下半分と重なる。ボスがこの帯にいると、ボス自身の弾も自機の弾も中央の足場で消えやすい。弾が薄い足場で消える仕様（`projectile.gd`）は変更していない。

### 移動先と移動

- `wander_area()` は `G.arena_zone(arena, 0)` と同じ範囲から、`body_size/2 + BOSS_CLEARANCE` を上下左右に引いた矩形。ボス中心が動ける範囲で、岩・壊れるブロックは含まない。
- 目的地は、到着（12px以内）、`retarget_clock` が0、`move_and_collide` で岩に衝突したときに選び直す。`retarget_clock` は選び直しごとに1.6〜2.8秒の乱数。
- 移動速度は `BOSS_MOVE_SPEED[role] * BOSS_WANDER_SPEED_RATIO`。進行方向に垂直な `sin(move_clock * BOSS_WANDER_WOBBLE_RATE) * BOSS_WANDER_WOBBLE` を加える。揺れで体が足場へ入る場合は、そのフレームだけ揺れを外して直進する。
- `wander_area()` の外（出現直後・再読込直後・突進後）では、範囲内の最も近い点へ `BOSS_RETURN_SPEED`（320px/秒）で衝突移動して戻る。瞬間移動はしない。
- 突進の `windup_charge`・`charging`・`charge_recover` は従来どおり移動しない。`roam` は出現位置と戻る先、既存検査のために残し、`boss_cycle.gd` の `roam_rect()` は変更していない。
- `wander_target` は原点移動時に `arena`・`roam`・`charge_target` と同じ量だけ移動する。区画の再読込では保存せず、復元後の最初の移動で選び直す。

### 候補の採点

候補ごとに次を合計し、最大の点を目的地にする。`PhysicsRayQueryParameters2D` の mask は `1 | T.PLATFORM_LAYER`、`PhysicsShapeQueryParameters2D` の mask は `T.PLATFORM_LAYER`。

| 点 | 条件 |
|---|---|
| +3 | 候補から自機への線に薄い足場も岩もない（`intersect_ray` が空） |
| +2 | 候補に `body_size` の体を置いても薄い足場と重ならない（`intersect_shape` が空） |
| +1 | 現在位置から240px以上離れている |
| +[0,1) | `RandomNumberGenerator` の乱数 |

乱数の種は `hash([game.current_seed, boss_id, boss_role])`。同じ seed・boss_id・boss_role と同じ初期状態なら同じ軌跡になる。

### 実装上の追加解釈

候補は10個作るが、全候補をアリーナ全体から独立に選ぶのではなく、左右どちらかの半分へ層化して置く。6回の目的地選択ごとに左右を切り替える（`BOSS_WANDER_SIDE_PICKS = 6`）。現在位置が体・射線とも安全で、その半分にいるときは現在位置を候補0として残す。左右を毎回選び直すと中央の棚帯を何度も往復し、棚と重なる時間が長くなったため、この追加規則を置いた。

目的地までは48px格子のA*で経路を作る。体が入る格子には80、射線が通らない格子には60の追加コストを与える。目的地が塞がっている場合は、目的地に近く現在位置から離れた安全な格子へ目標を置き換える。移動は従来と同じ `move_and_collide` で、岩に当たれば目的地を選び直す。

#### 経路計算のキャッシュ

- 体の安全判定は、ボスごとに48px格子を一度だけ作り、アリーナ内の薄い `PLATFORM_LAYER` の矩形との交差で求める。格子は `area.position` からの相対で持つため、原点移動では作り直さない。`area.size`・`body_size`・`boss_role`・格子数・地形改訂が変わったときだけ作り直し、ボスの `_ready` でも温める。
- 射線は96pxの粗い格子を使わず、48pxセルごとに遅延評価する。未問い合わせのセルだけ `intersect_ray` し、結果と問い合わせ世代を `PackedByteArray`/`PackedInt32Array` に保存する。同じ自機位置・アリーナサイズ・地形改訂の間は再計画でも結果を再利用する。`PhysicsRayQueryParameters2D` は使い回す。
- 目的地の補正も同じ射線キャッシュを使い、先に全セルを問い合わせない。補正候補が無い場合に全範囲の安全な格子を比較する動作は9F-3と同じ。半径4セルに限ると final の射線が目標を下回ったため、範囲は制限していない。
- A* の追加コスト、目的地の置換、返す経路の形式は変えていない。コスト・ヒューリスティック・open の優先度は64bit浮動小数で持ち、優先度と挿入順で比較する二分ヒープを使う。経路用配列、ヒープのノード領域、探索配列はボスの `_ready` で確保する。`_ready` 後の暖機では通常経路と不安全な目的地の補正を通し、戦闘開始位置であるアリーナ下端中央の射線結果を最後に充填する。
- 地形改訂はワールド全体で進むため、`_ready` 後の暖機だけでは初期ロード中に射線キャッシュが無効になる。ボスが未交戦の間は地形改訂と下端中央の自機位置を監視し、射線キャッシュを作り直す。負荷を1フレームへ集めないよう16セルずつ進める。経路結果は同じ `intersect_ray` の結果を先に保存するだけで変えない。
- 20回の最終実測（シード37、最初のガーディアン、1478×700）は初回2.172ms・中央値2.275ms・最大5.208ms・平均2.384ms。初回の内訳は格子0.005ms、初期化0.002ms、目標補正0.158ms、ヒューリスティック0.038ms、A* 1.953ms、組み立て0.007msで、射線キャッシュは命中し追加問い合わせは0。検査時の自機位置は暖機位置と一致する（アリーナ基準の座標で739, 904）。修正前は初回14.502msで、内訳は目標補正5.589ms・A* 8.323ms、射線422回だった。暖機時の地形改訂14に対し測定時が20で、キャッシュが無効になっていた。地形改訂の進行後も未交戦中に16セルずつ暖機し直すため、検査はその完了後に測る。検査は中央値3ms未満と初回6ms未満を確認し、平均・中央値・最大・各回・初回内訳を JSON に保存する。

### 自機がアリーナにいる間の画面外動作

`_player_in_arena()` は、ボスが `arena.has_area()` を持ち、自機が有効で死んでおらず、`arena.has_point(game.player.global_position)` のとき true。`engaged = on_screen or _player_in_arena()` とする。

- engaged の間は、画面外でも目的地移動、進行中の警告・`second_volley`・`spinning`・`charging`、ラスボスの常時回転弾を続ける。
- 新しい攻撃を `_choose_attack` で選ぶのは画面内のときだけ。画面外の idle では `shot_clock`・`signature_clock`・`switch_clock` も進めない。
- 起床待ちは engaged になったときに始める。画面外でもアリーナ内にいる間は、`was_visible` を画面内と同じ扱いにする。
- 自機がアリーナを出て、ボスも画面外なら、従来どおり移動を止め、攻撃を取り消し、`was_visible = false` にする。
- 自機が死亡している場合は engaged にならない。通常敵の動作と、画面内判定を使うアニメーション更新は変更していない。

## ラスボス撃破ごとの装備強化

2026-11-05。Task 9F-4。既存の装備購入、付け外し、周回強化は変更しない。

### 仕様

- `main.gd` に `upgrade_tokens` と `equipment_levels`（id → レベル）を追加した。`start_run` で強化権を0、レベル記録を空に戻す。`equipment_level(id)` は記録が無ければ1、記録があれば1〜`T.EQUIPMENT_MAX_LEVEL`（3）に収める。
- ラスボスの初回撃破処理で強化権を1つ加える。`defeated_bosses` の重複判定より後なので、同じボスの二重処理では増えない。中ボス（guardian）、secret、通常敵では増えない。チュートリアルでは付与も通知もしない。
- 通知は周回強化の `loot_message` を上書きせず、`T.LOOP_NOTICE + "　装備を1つ強化できる（商人の「強化」）"` として同じ枠に続けて表示する。
- 強化価格は `int(price * T.UPGRADE_PRICE_RATIO * 今のレベル)`、`UPGRADE_PRICE_RATIO := 0.5`。Lv1→2は購入価格の半分、Lv2→3は購入価格と同じ。
- `upgrade_reason(id)` の判定順は、商人の画面（`state == "shop"`）、所持、強化権、最大レベル、結晶の順。理由は「商人の画面で強化できます」「未所持」「ラスボスを倒すと強化できます」「最大」「結晶不足」。
- `upgrade_item(id)` は条件を満たすと結晶と強化権を1つずつ減らし、レベルを1上げる。装着中の装備なら同じ枠・同じidで `player.apply_equipment` を呼び直す。厚い外殻の最大HP増分は現在HPにも反映される。`play_sound("buy")` を鳴らし、連打は購入と同じ `SHOP_ACTION_INTERVAL` で制限する。
- 装備効果は `player.gd` の関数と `main.gd` の通常弾、`player.gd` の三連発射でレベル別配列を参照する。Lv1の値は既存定数と一致する。三連は発数 `n` に対し、`(i - (n - 1) / 2.0) * T.TRIPLE_SPREAD` の角度へ中央揃えで撃つ。
