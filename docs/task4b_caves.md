## 構成

- 全体を岩盤で満たし、14〜22空洞の位置・幅・高さを生成専用RNGで選ぶ。床高の帯は上416〜1120、中1152〜2016、下2048〜2944px。各シードで床高8種類以上、各地域で2帯以上を検証する。
- 開始空洞（幅896〜1408、高さ640px、X=6144を含み床Y=2304）と、各地域の中ボス空洞（幅1024〜1408、高さ576〜704px、地域内の位置と帯を乱数で選び、3帯を地域にランダムに割り当てる）を先に置く。
- 通常空洞（幅640〜1536、高さ320〜704px）は、置き済みの空洞を乱数で1つ選び、その左右か上下に置く。左右なら通路が届く128〜960px先で、床高の差は距離の半分かつ384px以内。上下なら縦穴が通るよう水平に288px以上重ね、64〜512pxの岩を挟む。ワールドの範囲外や他の空洞との64px未満の重なりは置き直す。固定の列や床高は使わない。
- 近い空洞の組から、他の空洞を貫かず施工できる通路・縦穴を候補にする。距離に乱数で重みを付け、到達集合から未到達空洞へ伸ばす木を作る。残りの候補をシャッフルして辺を追加する。独立閉路3〜8、採用辺数が候補数未満、次数1〜2と3以上の空洞の共存を検証する。
- 横通路は長さ128〜1024、高さ160〜256px。異なる床高の間を64pxごとの区間に分け、床を32px刻み、1段64px以下でつなぐ。低い天井で使う短いジャンプも手順に記録する。
- 縦穴は両空洞が水平に重なる範囲から位置・幅160〜320pxを選ぶ。足場間隔96〜160px、横の重なりは自機幅+着地余白以上。同じ空洞へ上から入る縦穴は最大1本とし、下の床を基準に足場の高さを決める。縦穴の足場も含め、空洞内に収まる薄い足場を1〜4枚とする。
- 通常空洞の50%以上に床の段差0〜3個（32〜128px）、30%以上に床の突起または垂下岩0〜2個を置く。薄い足場の位置・幅・高さも変える。垂下岩は段差の上でも160px以上空け、ジャンプ経路を塞がない。
- 通常敵は目標40体、許容36〜44体、各空洞5体以下。立てる面から位置を選び、飛行敵は条件を満たす床・足場上の区間からレーンを選ぶ。全7種を含み、breaker・flyer・laser合計45〜60%、1種類30%以下。直線射撃の4種類を40%以上残す。開始・中ボス空洞の通常敵、通路・縦穴の敵は0体。
- ブロックは床・段差・薄い足場の候補から選び、目標10個、6個以上を2地域以上へ分散。出入口、往復手順、敵の体・巡回範囲・飛行レーンを避け、設置後の射線を維持する。

## 維持した保証と調整

立てる面の有向グラフで、歩行・通常ジャンプ・落下・すり抜けによる全節点の強連結を調べる。全指定面を64px削った場合も検証し、中ボスごとの行き・帰りの手順を作る。短い面への踏切と着地も扱う。外部の`validate`は常に地形からグラフを作り直し、通常生成中だけ直前に構築したグラフを再利用する。

同じ高さの穴を越すジャンプは、実測した跳躍から届く最も低いものを選ぶ（Task 4B-3）。以前は常に最も高いジャンプ（頂点約170px）を手順にしていたため、床を削った穴の上に96px上の薄い足場があると、落下中にその足場へ乗ってしまい、手順どおりに着地できなかった。実測値は `tuning.gd` の `HOP_PROFILES`（静止から右へ進みながらジャンプを押す時間 → 足の最高点・平地での着地距離）。

| 押す時間 | 最高点 | 着地距離 |
|---:|---:|---:|
| 1フレーム | 62.5px | 90.6px |
| 2フレーム | 81.1px | 101.2px |
| 4フレーム | 114.5px | 122.6px |
| 6フレーム | 143.1px | 138.6px |
| 8フレーム | 166.7px | 159.9px |

着地距離が「踏切から着地点まで＋12px」以上の最短のものを使い、その高さまでの弧に薄い足場（乗ってしまう）か岩（頭が当たる）があれば辺にしない。

Task 4B-4では、`movement_test`で5種類すべての高さ・距離を実物理で測り直した。8フレームは切り上げ時にまだ上昇速度が650px/sを超えるため、長押しの最高点170.1pxには届かず166.7pxとなる。表を実測に合わせ、32pxの穴・96px上の薄い足場の下での左右の往復と、岩の天井・高い跳躍を受け止める薄い足場の拒否も追加検証した。移動の物理値は変更していない。

射線は既存の発射口、レーザー曲線、1秒の放物線を使用。岩・薄い足場・ブロックを検査する。既に確認した射線を塞ぐブロック候補では、別の接近点への射線を調べ直し、全敵の射線が残る場合だけ採用する。実際の通常射撃の方向と発射口のずれも調べ、弾道が接近点の自機の体へ届くことを確認する。

床の表面64px、開始・中ボスと出入口周辺96px、縦穴下の保護は継続。段差の踏切、薄い足場へ戻るための幅64pxの踏切面、坂状の通路の段差部分も保護する。指定する削れる面は厚さ128px以上の岩に限定し、64px削っても床を残す。削れない壁・天井・薄い足場と深い岩盤、地域境界での状態保持、再挑戦での復元は継続。

移動・ジャンプ・戦闘の数値、操作、ロードのない一続きのワールドは変更していない。

## 生成時間（Task 4B-3）

中断時点の生成は1シード平均529.7ms・最大1,468.5ms（1,000シード）で、主な原因は配置の試行だった。空洞を全体から一様に選んでいたため、通路・縦穴の候補が足りず約95%の試行が捨てられ、1シードあたり平均約143回試行していた（全500回失敗して作り直すシードもあった）。

- 通常空洞を置き済みの空洞の隣か上下に置く方式に変え、ほぼ1回の試行で配置が決まるようにした（配置は約55ms → 約1.4ms）。この変更で同じシードから生成される地形は変わる。性質の検査は従来どおり。
- 結果を変えない高速化: 到達グラフでジャンプ先を高さの範囲だけに絞る、岩をx方向の区画で引く、要素ごとの関数呼び出しを通常のループにする。レーザーの曲線を、ノードを作らない静的関数（`laser_beam.gd` の `curve_points`）で計算する。射線と立ち位置の判定を、経路や空洞の近くの岩だけで行う。60シードの生成結果（signature）が高速化の前後で一致することを確認した。

## フォールバック

`scripts/cave_fallback.gd` は乱数を使わない固定の非常用データ。通常の生成が12回続けて検証に失敗したときだけ使う（1,000シードでは0回）。生成の規則を変えたら次で作り直し、`tests/generation_test.gd` を実行する。

```powershell
$env:APPDATA = "$PWD\.userdata"
& .\tools\godot\Godot_v4.7.2-stable_win64_console.exe --headless --path . --script tests/regenerate_cave_fallback.gd
```

シード4242の通常の生成結果を `fallback = true` にして書き出し、読み戻して `validate` を通ることと内容の一致を確かめる。`generation_test.gd` もシードごとにフォールバックの `validate` と再現性を検査する。
