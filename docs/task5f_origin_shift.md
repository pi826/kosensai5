# Task 5F：原点の移動

2026-10-26。5A〜5Eの未コミット変更を保持して実装。コミット・プッシュ・公開・デプロイは行わない。

## 方式

- `main.origin_sector` が現在の原点に対応する整数区画座標。自機の相対区画座標の各軸の絶対値が2以上になった物理フレームの先頭で、その区画座標を原点へ加える。全移動量は `-相対区画座標 × (4096,3072)` px。判定値は `tuning.gd` の `ORIGIN_SHIFT_SECTORS`。
- 優先順位-100で、区画処理・自機・敵・攻撃の物理更新より先に一度に移動する。ノードの置換、衝突形状の再生成、待機画面、ワープを行わない。衝突ノードは移動直後に `force_update_transform()` を呼ぶ。
- 自機・すり抜け終了の高さ・カメラの追従途中の位置、地形の衝突・描画・背景、敵・飛行中心・巡回範囲・休止位置、ボスの空洞・往復範囲、弾と軌跡、誘導弾、レーザーの曲線・照射経路、砲弾・着弾印・予告、設置壁と設置予告、ハート、効果とHP表示を同量移動する。速度・方向・追尾対象・HP・色・タイマーは変えない。地形の親だけでなく各StaticBody2Dにも `force_update_transform()` を適用し、そのフレーム内に物理サーバーへ伝える。
- 地形セルと描画バッチの索引は整数の世界キーを維持し、原点移動で全セルを走査しない。物理・描画へ渡すときに整数で原点差を取ってから `Vector2` へ変換する。
- 生成ジョブは起動時の原点を保持する。完了・join後に現在の原点との差を適用する。ワーカー実行中の結果には触れず、追加途中の地形・敵も現在の原点へ合わせる。生成の中身・順序非依存性はシードと区画座標のまま。

## 長く残るデータ

| データ | 保持方法 |

| 区画の識別・生成・訪問・ボスの使用済み区画 | 整数区画座標 |
| 解放した区画の敵位置・飛行中心、床の破壊・箱のHP | 区画キー＋区画内ピクセル位置／セル |
| 消失・復活の対象位置と除外範囲 | 区画キー＋区画内の記述・矩形。消失時刻・試行番号は不変 |

| ボスの位置・空洞・移動範囲・保存した移動状態 | 区画座標＋区画内座標。画面・ノード用の値は必要時に変換 |
| 地図のボス印 | 区画座標＋区画内位置 |
| 探索済みセル・地形セル | 整数の世界セルキー。解放済みの地図形状は各地図セル内の矩形 |

再挑戦では原点と移動回数・計測、区画・探索・復活・ボス記録を初期化する。チュートリアルは従来の独立した固定練習場で、原点移動を使用しない。

## 精度

120フレーム、320px/秒、期待距離640pxの単純な床の実験で、途中に原点移動を1回入れる。原点区画 `(0,0)`、`(50,-20)`、`(100000,-50000)`、`(-100000,50000)` を同じ相対座標で比較する。遠方の実生成・物理・戦闘・保存は追加検査で別途確認する。

最終計測：全4地点とも歩行639.980590820313px、距離誤差0.00303268432617188%、床の高さ誤差0.0747623443603516px、接地成立。原点付近との差0px。

4種類の100フレームの移動経路では、原点付近と遠方の位置差0px、速度差0、接地一致。原点移動しない対照経路との差は最大0.03125px。すり抜けは2段の薄い足場を使い、下キーを離して次の足場へ着地することも確認した。実生成区画 `(100000,-50000)` では、24フレームの加速を含む期待114.6666667pxに対して114.6650390625px、床の誤差0.074737548828125px。敵弾の命中と吸収、自機誘導弾での撃破、区画の解放と状態復元も確認した。

通常描画の前後画像は `builds/qa/origin_shift/before.png` と `after.png`。最終比較は333バイト差／3,686,400バイト（0.0090332%）で、目視でもカメラ・地形・攻撃・ハート・効果の移動の飛びは見られなかった。画像の不完全な一致をゼロ差とは扱わない。原点移動は終盤の保持11区画の検査系列で最大10.314ms、別の同時実行系列で最大41.758ms。これらは単独実行の性能保証や前後の速度比較には使わない。
