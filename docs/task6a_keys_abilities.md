# Task 6A：結晶・鍵と宝箱・移動能力

2026-10-26実装、10-27検証。6Bの商人・装備・回復薬は含めない。再挑戦時は通貨・鍵・全能力・開封・収集を全て初期化する。

## 実装

- 結晶は通常敵5、ガーディアン50、ラスボス150、裏ボス300。撃破済みIDに加えて個体に通知済み印を付ける。復活でIDの撃破状態が解除されても古い個体の通知では再加算しない。新しい復活個体には再び報酬を与える。吸収は従来の誘導弾ゲージだけ。HUDに結晶と鍵、結果に獲得した結晶の合計、頭上に紫の加算数値を表示する。誘導弾の白い数値とは位置も分ける。
- 鍵は接触取得。未開封の箱から68px以内で現在の「調べる」を押すと鍵を1つ消費する。鍵なしは1.4秒の案内。能力は4秒の名前と現在のキー設定による説明。箱の中身は `contents: [{kind, ...}]` の配列で、6Bの種類を追加できる。通常の箱は結晶30〜80。
- 永続IDは整数の区画座標＋区画内位置。開封・収集はラン所有の `loot_taken`、発見記録は区画座標＋区画内位置の `discovered_loot`。ガーディアンの鍵はボスIDと同じ形式の位置記録に保持する。区画解放時は実体だけを破棄し、再読み込みで開いた箱を復元する。鍵と箱は45秒の復活処理へ入れない。原点移動では実体と描画用の位置だけを移し、永続記録は変えない。
- 地図は画面に入った鍵・宝箱だけを記録する。取得・開封で印を消す。鍵は金の輪と柄、普通の箱は金の矩形、能力の箱は紫の菱形。
- 二段ジャンプは着地まで1回、通常ジャンプの85%の初速。短押しの切り上げを共用し、コヨーテ時間中は通常ジャンプを優先する。空中ダッシュは地上で無効、向いている方へ960px/秒、0.18秒、着地まで1回。重力を止め、壁で終了する。固定60Hzでは11フレーム・176px。滑空は下降中のジャンプ長押しで上限120px/秒、離すと通常落下。二段ジャンプが残る押下では先に二段ジャンプを使う。チュートリアルは能力判定を無効化する。

## 配置と到達

- 地形の乱数から独立した `(seed, 区画座標, loot)` の乱数を使う。能力の割当も専用の乱数で生成順に依存しない。二段ジャンプは開始区画、空中ダッシュはチェビシェフ距離2〜3、滑空は2〜4。割当先は別々。3つとも初期能力で往復できる支持面上に置く。
- 開始区画には鍵を必ず1個置き、最初の鍵と二段ジャンプの箱は開始位置に近い順に選ぶ。その他の区画は鍵確率0.82、通常の箱確率0.65、各0〜1個。体・巡回範囲・飛行レーン・地形・壊れるブロック・ハート・他の収集物を避ける。追加ボスの移動範囲も収集物を避ける。
- 寄り道は空洞内の高い棚や、水平に離れた上段の棚。二段ジャンプ、二段ジャンプ＋空中ダッシュ、全能力のいずれかを条件に選ぶ。実測した入力手順による到達グラフで、前の能力の組では届かず、条件の能力では届き、初期能力で床へ戻れる候補だけ採用する。条件を満たす棚を置けない区画には無理に追加しない。床・ゲート・ボスへの経路を残す。報酬は結晶40。
- `navigation_graph` に能力ビット集合（1=二段ジャンプ、2=空中ダッシュ、4=滑空、組は論理和）を渡す。既存の辺へ `ability_jump` を追加する。60Hzの入力手順と同じ加速・ジャンプ・重力・ダッシュ・滑空の軌道で体の矩形を掃引し、岩・途中の着地を拒否する。実物理の測定表 `ABILITY_HOP_PROFILES` で高さと距離も制限する。通常経路の全支持面は従来どおり初期能力で強連結、追加の寄り道の支持面だけを別条件として検証する。通常地形・最大掘削後の両方を確認する。

## 再開時の差分判断

2026-10-27の開始時に、README・文書・scripts・tests・scenesを作業用の写しとSHA-256で照合し、相違は指定された3ファイルだけだった。

写しの stage_generator.gd の optimistic_reachable、tuning.gd の REACH_HEIGHT_MARGIN=24、loot_generator.gd の前段階の物理上限による除外は、3つとも不採用にした。そのまま反映した確認実行は947項目・1失敗・終了コード1。64シードで二段ジャンプ以外の2種類の寄り道が生成されず、「3種類を生成する」の項目が失敗した。障害物を無視した大きな上限の内側にあることは到達の証明ではないが、この案はそのような候補も全て破棄するため、既存の生成条件と両立しなかった。探索中の別案も最終ソースには残していない。

有限の実測入力手順による前段階の到達グラフ検査は維持した。任意の入力手順による完全な到達不能性は未証明であり、上限案を不採用にしたことによって証明済みとは扱わない。

## 生成時間の修正

原因の主成分は寄り道の候補ごとの能力軌道・射線検査とグラフ再構築だった。64区画の計測で、修正前は生成301.221msのうち寄り道127.827ms、配置全体145.786ms、地形本体155.347ms。修正後は生成134.947ms、寄り道30.910ms、配置全体35.636ms、地形本体98.986ms（計測用処理を含む。寄り道は配置の内数）。能力軌道の試行は53,377回から21,412回へ減った。

- 検証済みの通常・掘削後グラフを配置へ渡す。薄い棚の追加では既存の支持面と影響しない辺を再利用する。外部の検証は従来どおり全グラフを独立に再構築する。
- 既存の通常グラフのジャンプ・すり抜けで届く候補、前段階の能力で届く候補を先に除外する。軌道・射線・通常と掘削後の往復の検査は残す。
- 障害物のx索引とその検索結果、入力手順、敵の全巡回範囲・飛行レーンを同じ生成処理内で再利用する。矩形の直接検索と支持面の早期判定で、繰り返す配列コールバックを減らした。共有・全体キャッシュは使わない。

同一64区画の単独実行は平均283.112→127.762ms、最大1,282.160→727.438ms。生成データ全体を文字列化する `S.signature()` のSHA-256は64区画全て修正前と一致した。乱数列、候補の順番、報酬と配置条件は変えていない。

| 同・最大 | 2,003ms | 1107.828ms |

streaming_test の開始時の生成は seed 1: 829.380ms、seed 37: 979.763ms、seed 2026: 883.914ms。修正前の報告値は約1,879ms。区画検査内の平均は159.318ms、最大2132.076ms。約150msという今回の生成目標は156.586msで満たしたが、以前からの平均80ms・最大400msという別の性能目標は未達。CPUやシードによる最悪時間を保証する数値ではない。
