# 上下左右に続く区画の世界

2026-10-26、Task 5B-2 / 5C / 5D。区画の実装・実測・検査は [task5b_streaming.md](task5b_streaming.md)、生成は [task5b_sectors.md](task5b_sectors.md)、報酬・回復・復活は [task5c_rewards.md](task5c_rewards.md)、ボスの進行は [task5d_bosses.md](task5d_bosses.md) を参照。
操作・ジャンプ・HP・接触判定・無敵時間は Task 4A / 5A の値を維持する。

## 地形と生成

- 区画は4,096×3,072px、地形は32pxグリッド。負の区画座標も含め、上下左右に人工的な外周を設けない。
- 区画の中身は `(seed, i, j)`、共有ゲートは `(seed, 境界の所有者, 方向)` だけで決定する。生成順・移動履歴には依存しない。
- 各辺に1〜2個のゲート。不規則な空洞、段差通路と縦穴、足場、突起・垂下岩、壊れる床・ブロック、通常敵14体を配置する。全ての立てる面とゲートが、通常・床の最大掘削後とも歩行・通常ジャンプ・落下・すり抜けで往復可能なことを検証する。
- 開始は区画 (0,0) の `(1024,1738)`。初回ガーディアン3体は `guardian_sectors(seed)`。3体撃破→ラスボス→新しいガーディアン3体を繰り返し、ラスボス3回→裏ボス→撃破でクリアする。

## 読み込みと解放

`sector_job.gd` は WorkerThreadPool 上で生成・検証・ワールド座標変換・地形セルの準備を行う。SceneTreeと物理ノードには触れない。完了したタスクだけをメインスレッドから回収する。

開始時は中心と周囲8区画を完成させてからプレイヤーを出す。移動中はチェビシェフ距離2以内を先読みし、通常2タスクまで並行生成し、3秒先の移動方向に近い候補を優先する。地形の衝突・セル・行衝突・薄い足場・接続マスク・敵・収集物・商人・ボス・背景をメインスレッドで時間枠ごとに追加し、これらが揃った区画を「完成」とする。画面外の描画命令の作成は完成条件から分離する（Task 7E）。
地形の描画チャンクはツリーへ入れる前に隠し、再描画を整数座標の待ち行列へ集約する。現在と次のカメラ視界に移動量と余白を加えた範囲は、上限にかかわらず描画を要求する。画面外は、必須範囲の外側 `T.STREAM_DRAW_PREFETCH_MARGIN`（1024px）以内の待ちチャンクだけを、移動方向の先読み点に近い順に1フレーム最大1個描く。それより遠いチャンクは隠したまま待ち行列に残し、近づいたときに描く。全キーの毎フレーム走査は行わない。取り込み時間と実測描画コストから残り枠を見積もり、待ち行列の管理時間は提出の可否に含めない。取り込み・敵追加などの仕事の有無は明示的なフラグで判定し、同じ描画フレームで物理が複数回動けばフラグをOR、時間を合計する。仕事と視界内の更新がないフレームでは、推定コストが枠を超えても1個進める。開始直後も視界とその周囲だけを先に描く。
背景も区画完成時に全データとノードを揃え、視界とその周囲に入るチャンクだけ描画命令を作る。画面外の背景の初回描画を区画完成フレームへ集中させない。
現在と次の移動で入り得る区画の周囲8区画、視界の区画完成、および余白込みの視界内に未提出の再描画がないことを確認してからシミュレーションを進める。物理での地形変更後も描画直前に視界を再確認する。区画の追加・解放、破壊・復元、設置壁の点滅にも同じ待ち行列を使う。原点移動では整数キーとチャンク内の描画命令を保つ。

中心からチェビシェフ距離3以上で、かつプレイヤーから区画矩形までの軸別距離を区画幅・高さで割った最大値が2.25以上の区画を解放する。地形データの後片付けは複数フレームに分け、セル128個、surfaces 128個、ブロック1個、本体16個、行1行、描画チャンク1行分ずつ進める。解放中は新しい区画の取り込みを始めず、1フレームに最低1段階進める。境界付近は余白2.25未満の帯を保持し、往復による読み込みと解放の反復を防ぐ。
先読みが遅れた場合は、最後の完成済み画面で世界・攻撃・時間を保留し、取り込みと再描画の待ち行列は進める。仮の壁、座標の補正、ワープ、ロード画面は使わない。7E前は実時間の歩行でも保留が発生していた。変更後の固定fps・実時間の測定値は [Task 7E](task7e_stream_install.md) を参照。固定fpsのheadless検査は実時間より速く移動するため、保留0を保証するものではない。

区画を追加・解放しても世界・プレイヤー・弾のコンテナを置き換えない。床・壁・天井の矩形は共有ゲートの座標に接続する。描画は読み込み中の全区画のセルを共有する辞書で8近傍を調べ、追加・解放時に境界の両側と斜めを更新する。

## 状態

- 区画座標をキーに、破壊した床セル、全ブロックの残耐久、敵の位置・HP・ゲージ・色・速度・各タイマー・飛行位相を保存する。
- 敵の永続IDは `区画x,区画y:ローカルID`。撃破記録を別に保持し、読み込み時に撃破済みの敵を生成しない。ガーディアンの撃破・発見は解放後も残す。
- 弾・砲弾・レーザー・設置壁は区画解放時に消す。画面外の敵は攻撃しない。復元した敵は画面に入ったとき通常の待機時間を置く。
- 地域の境界・区画の境界では状態を初期化しない。死亡後の再挑戦は同じシードで、全区画の状態・探索・撃破・スコアを消して開始する。
- 5D: ボスの周回・ラスボス回数・個体ID・場所・HP・生死・移動位相を `BossCycle` へ保持する。追加配置は別スレッドで既存の通常空洞を選び、区画完成時に追加する。空洞内の通常敵とその5C復活を抑止する。解放時に位置・HP・ゲージ・速度・攻撃タイマーを保存し、再読込は生存個体だけ復元する。予告は破棄して通常の起床待ちから再開する。死亡・再挑戦でボス進行も初期化する。
- 5C: 通常空洞の立てる面にシード・区画座標から0〜2個のハートを置く。敵の巡回・飛行範囲、岩・箱を避け、開始・ガーディアンの空洞と地図には置かない。
- 消えた通常敵・箱・ハートは独立した復活記録を持つ。45秒経過後、5秒ごとに25%で復活する。視界+96pxとプレイヤー・設置壁・敵の体を避ける。敵は体と巡回範囲をまとめて判定し、HP満タン・ゲージ0・通常の画面内待機から再開する。床が削れて支持を失った地上敵は元の場所へ戻さない。
- 解放中も同じゲーム内時刻とID・消失時刻・試行番号からの乱数で判定し、戻る場合は保存状態だけを更新する。生成ジョブが保存状態を所有している間は区画完成まで判定を保留し、その後に経過した試行を処理する。床の掘削とガーディアンの撃破は復活しない。

## カメラ・攻撃・地域

カメラに地形の外周による制限はなく、上下左右へ追従する。弾と砲弾は完成済み区画の外に出ると消す。レーザーは完成済み区画の境界と実地形で止める。単に読み込み区画を包む矩形の内部かどうかでは判定しない。

地域はシードによる4×4区画のまとまりから決める。名前・背景・岩の配色は区画の地域に従い、上下左右の境界384pxで滑らかに混ぜる。遠方でも背景の模様は同じワールド座標に固定する。

地域の曲はカメラ中心の地域に追従してクロスフェードする。音の切替に区画の読み込み・ワープ・地域の再生成は伴わない（Task 8A）。

## 地図・HUD

地図はプレイヤー中心の横3区画分で、縦の範囲は表示枠の比率に合わせる。探索セルは整数座標で無制限に記録し、区画別の索引も持つ。解放前に探索済みセルの実地形を保存するので、壊した地形も解放後の地図に残る。
描く範囲のセルだけを調べ、探索全体を毎フレーム並べ替えない。

文字の凡例を表示せず、自機の白点・視界枠・ボスの菱形・撃破チェックを描く。初回ガーディアンは発見後、追加・復活ボスは出現時から表示し、範囲外は縁の方向印を付ける。ラスボスは金、裏ボスは紫の輪付きの印。
HUD・一時停止・結果の探索は訪れた区画数、通常敵は撃破数だけを表示する。

## 性能と精度

7Fでは生成結果を維持し、200区画の生成平均を91.33／91.40→66.78／66.69msへ短縮した。50ms以下は未達。一致比較と残る負荷は [Task 7F](task7f_generation_speed.md) を参照。

調整値は `tuning.gd`。生成のグラフは、ブロック追加の影響がないx範囲の辺を再利用し、影響範囲と変化した立ち位置は作り直す。外部の検証では全グラフを独立に再構築する。外周検査はその辺に接する岩だけを調べる。
画面外で静止した敵は、地形の更新や位置変更時に床の衝突を再検査する。画面外への再描画要求と変化のない照準印の更新を省く。

開始時間・移動中のメイン処理・物理処理・区画生成の実測は [検証報告](task5b_streaming.md) にまとめる。
5Fでは、自機の相対区画座標の各軸の絶対値が2以上になると、区画の整数倍だけ世界・カメラ・衝突・攻撃を同一物理フレーム内で移動する。長期記録は整数の区画座標と区画内位置を用い、描画・物理には原点との差を渡す。遠方の精度と検証は [task5f_origin_shift.md](task5f_origin_shift.md) に記載する。
