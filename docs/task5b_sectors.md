## 決め方

- `generate(seed, Vector2i(i,j))` は4096×3072pxのローカル座標データを返す。負・遠方の区画座標も扱い、生成履歴・共有キャッシュ・時刻・SceneTree・グローバルRNGには依存しない。専用RNGは `(seed,i,j,試行番号)` の文字列ハッシュから作る。32bitハッシュの衝突を排除する保証はない。
- まず全ゲートの内側に入口空間を置く。角付近で重なる入口は一つの空間に併合し、上側ゲートから広がった入口の床まで足場を延ばす。開始区画には開始空洞、ガーディアン区画には専用空洞を置く。
- 通常空洞は置き済みの入口・空洞を乱数で選び、左右・斜め・上下に追加する（斜めは7Cの追記）。目標数4〜7個、置けた数が開始／ボス区画で3個以上、その他で4個以上なら候補を作る。幅640〜1152px・高さ384〜512px、位置・床高は32px刻み。同じ区画の空洞の床高は重ねない。開始空洞は幅1152px・高さ640pxで開始位置を含む。ボス空洞は幅1024〜1408px・高さ576px。
- Task 4Bの `_candidate` を使って段差通路・縦穴の候補を作る。任意のゲート高に対応するため、縦穴と横通路が折れ曲がる候補も加える。空洞や他の接続を横切らない候補から木を選び、追加辺を0〜3本選ぶ。縦穴のxは重なる範囲から乱数で選ぶ。折れ曲がる通路が空洞の上部へ開く場合は、その口から縦穴まで薄い足場で渡す。
- `_decorate` を共用し、床の段差0〜3個、床の突起・垂下岩0〜2個、空洞内の足場1〜4枚を配置する。位置・幅・高さを乱数で変える。通常空洞の半分以上に段差、30%以上に突起または垂下岩があることを検証する。縦穴の足場も含めて空洞内の足場数を検査する。
- 立てる面からブロック候補を作り、シャッフルして4個を選ぶ。候補の組を置いた後、通常・床を削った状態の強連結を確かめ、失敗した組は選び直す。敵は床・足場の候補を乱数で選び、ブロックと巡回範囲・飛行レーンの余白を確保する。通常敵14体・全7種類、1空洞5体以下。breaker・flyer・laser合計45〜60%、1種類30%以下を区画単位で検証する。射線・支持面・巡回・飛行レーンは既存処理を共用する。
- 開始・ボス空洞、出入口96px、通路の段差、縦穴、足場や段差への踏切を保護する。指定した床の表面64pxだけを削れ、下に岩が残る面に限定する。
- 配置候補の再試行と、同じ掘り抜きに対する内装の再試行を分ける。完成した地形の検証を通した結果だけ返す。通常生成内では直前の到達グラフを再利用し、外部からの `validate` は地形から作り直す。

## 到達・フォールバック

`validate` は寸法・岩の間隔・段差・突起・垂下岩・足場・通路・縦穴・削れる床・保護範囲・敵・ブロック・全ゲートを検査する。岩・薄い足場・ブロックの実体から有向の到達グラフを作り、通常と全指定床を64px削った状態の全ての立てる面が強連結であることを確認する。ゲート内側の立ち位置も含める。

`combined_stage` は任意の区画集合をワールド座標へ移して合成する。`navigation_graph` はその実地形のグラフを作り、`seam_errors` は両側のゲート・開口・岩と、開口付近の双方向通過を調べる。`guardian_routes` は実際の `walk / jump / drop / drop_through` による行き・帰りの手順を返す。架空の区画間の辺やワープは使わない。

所定の3試行を使い切った場合は、乱数を使わない非常用地形へ切り替える。両端の足場列と単純な通路で空洞と任意のゲートを結ぶ。ゲートと近い高さの足場が互いを塞がないよう、通路側・境界側で足場の横位置を分ける。敵14体・ブロック4個を含め、通常と同じ `validate` を通す。`generate(seed,coord,0)` でこの分岐を強制できる。
