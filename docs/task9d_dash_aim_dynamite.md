# Task 9D：ダッシュの方向転換・振動と残像、射撃方向の矢印、指向性ダイナマイト

2026-11-03。Godot 4.7.2 / GDScript。一続きの探索、同色吸収・異色ダメージ・発射後の弾色保持、Task 9A〜9Cのうち下で変えると書いていない挙動を維持する。

## 空中ダッシュ

- 方向は画面基準の8方向。左右と上下のキーの組み合わせを正規化した向きへ進む（例: 上＋右で右上）。方向キーを押していなければ向いている横方向。Task 9Bの「上下優先」は廃止した。重力反転中も画面基準。
- ダッシュ中も、方向キーを押している間はその8方向へ向きを変える。離すと最後の向きを保つ。速さ AIR_DASH_SPEED（960px/秒）と時間 AIR_DASH_TIME（0.18秒・11フレーム）は変えず、向きを変えても延長しない。横成分があれば向き（facing）も合わせる。
- 最後の1フレームは向きを変えない。そのフレームに押しているキーはダッシュ後の横速度だけに使う。地形生成の到達計画（stage_generator.ability_arc）の上ダッシュは「真上へ11フレーム、最後のフレームで横キーの速さ」を前提にしており、実入力の検査は `ability_steer_paused` の間だけ横キーを離して同じ軌道を再現する。人の操作では1/60秒のことなので体感には影響しない想定。
- 終了条件は、時間切れ・着地・重力反転に加え、そのフレームの実移動のうちダッシュ方向の成分が AIR_DASH_SPEED×delta の1/4（AIR_DASH_BLOCKED_RATIO）未満になったとき。斜めに壁へ当たると壁に沿って進み、真っ直ぐ塞がれたときだけ止まる。
- 終了時の速度は、横は今と同じく横キー×移動速度。縦は重力の向きへ進んでいたとき MAX_FALL_SPEED×dash_vector.y、それ以外は0（真上・真下・真横は従来と同じ値）。
- 1回の空中で1回、着地で回復、地上では出ない、重力反転で取り消し（回復なし）は変えない。生成の飛行スケジュール（ABILITY_FLIGHT_SCHEDULES）と計測表は変えていない。8方向と方向転換は到達範囲を広げるだけ。

## 画面振動と残像

- ダッシュ開始時だけ、DASH_SHAKE_PIXELS（3px）・DASH_SHAKE_TIME（0.12秒）の線形に減衰する振動。乱数は使わず時間の sin/cos で決める。方向転換では振動しない。
- 振動は `camera.offset` だけで表す。`camera.position`・view_rect・読み込み範囲・画面内判定・カメラ追従は振動を見ない。main の `apply_camera_offset` がボス撃破演出の振動（`impact_shake`）とダッシュの振動を足し、両方が終われば offset は正確に0。boss_impact はこの関数を使うよう変更し、見た目の振幅と時間は変えていない。
- 残像: ダッシュ中2物理フレームごと（開始フレームを含む、11フレームで6枚）に自機の絵（体と腕、向き、重力反転の上下反転）を記録し、0.2秒で不透明度0.6から0へ消す。自機の現在の色で染め、加算合成で暗い背景でも光って見えるようにした（通常の合成では暗い影になった）。同時に最大8枚。画像が無い描画では体の矩形の輪郭。
- 残像は effects の子ノード `DashAfterimages`（scripts/dash_afterimages.gd）。絶対 z_index −1 で、地形より手前・敵と自機より奥。当たり判定・ゲームの状態を持たない。原点移動では effects の子として世界と一緒に動く。自機の死亡で消え、run の開始で世界ごと作り直す。

## 射撃方向の表示

- 上部の帯の「現在の色」（色アイコン・色名）と「射撃方向 前/上/下」の文字、帯の矢印を削除した。空いた場所は詰めていない。誘導弾ゲージの色・ボスの色アイコンは変えていない。自機の色は自機の絵で分かるため代わりの表示は作らない。
- 射撃方向の切替（既定 L）を押したときだけ、自機の中心から射撃方向へ AIM_INDICATOR_DISTANCE（72px）の位置に、射撃方向を向いた矢印を AIM_INDICATOR_TIME（0.5秒）表示する。最初の0.3秒は不透明、残り0.2秒で消える。表示中は自機の位置・向き・重力反転に追従し、続けて押すと時間を最初からにする。run 開始時・死亡中は出さない。チュートリアルでも出る。
- 矢印は effects（z 5）に描く、自機の色の山形と軸（濃い縁取り付き）。ボスの方角矢印が同じ画像で自機の周り70pxに出るため、混同しないよう画像を使い回さなかった。

## 指向性ダイナマイト

参考にした Terraria の Scarab Bomb は粘着爆弾の一種で、爆発の時点で自機と反対の方向へ長さ21・幅3タイルの細い穴を掘る。本作のタイル32pxと自機30×44pxに合わせて次のようにした。

- 投げ方・画面下向きの重力（重力反転の影響なし）・導火線1.6秒・入手・所持3個は Task 9C と同じ。

Task 9E で通常敵3体ごと・上限20に変更（task9e_dynamite_barrage_demo.md）。

- 粘着: 岩・ブロック・壁・薄い足場に最初に触れた位置で止まり、触れた面を覚える。毎フレーム、その面の方向へ2pxの test_move で支えを確かめ、無くなれば再び落ちて次に触れた所で止まる。壁や天井にも張り付く。
- 方向: 爆発の時点で `爆弾の位置 − 自機の中心` の大きい軸の、自機から離れる向き（画面基準の上下左右）。縦横が同じなら横。自機と同じ位置、または自機が死亡しているときは投げたときの向き。
- 地形: 爆弾の中心を含むセルから、その方向へ DYNAMITE_SHAFT_LENGTH（11）セル、垂直方向に DYNAMITE_SHAFT_WIDTH（3）セルの長方形（352×96px）を壊す。丸い穴は掘らない。壊す対象・規則（深い岩も消す、ブロックは自機の攻撃扱い、設置壁も消す、薄い足場は残す、protected_rects を無視、読み込み済み区画だけ）と、衝突矩形の分割・保存と再読込・原点移動・地図への反映は Task 9C の仕組みのまま。保存の cuts が正方形から長方形になるだけで、記録の形式は変えていない。
- ダメージ: 長方形と、爆弾の中心から DYNAMITE_CORE_RADIUS（48px）の円の和に体の矩形が重なる者に1回。値（自機20、敵8）と敵→自機の順は同じ。方向の反対側や長方形の横にいる者は無傷。
- 表示: 燃えている間は、今爆発したら壊れる長方形の薄い輪郭を描く（自機が動けば向きが変わる）。爆発は長方形の閃光と、2セルおきに外へ順に広がる爆発の絵（0.45秒）。

## 変更した既存検査と理由

- tests/gravity_test.gd: 「上＋右は真上（上下優先）」を「右上（正規化）」に変え、「下＋左は左下」を足した。終了時の縦速度の期待値を `MAX_FALL_SPEED×dash_vector.y` に一般化。上下優先の廃止による。
- tests/run_tests.gd: HUD の `angle_label` の文字の検査2か所を、切替直後の矢印の表示・位置の検査と、HUD に射撃方向の文字が無い検査に置き換えた。表示の移動による。
- tests/impact_effect_test.gd: 「撃破演出の後 camera.offset が0」を「演出の振動（impact_shake）が0、かつダッシュの振動が残っていなければ offset が0」に変えた。この検査は物理処理を止めたままダッシュを1回行うので、ダッシュの振動が減衰しない。演出側の後始末は従来どおり検査している。
- tests/ability_physics_test.gd・tests/ability_driver.gd・tests/ability_generation_test.gd: 上ダッシュの飛行スケジュールの実入力で、`ability_steer_paused` の間（ダッシュ開始から最後の1フレームの前まで）横キーを離す。従来どおり横キーを押したままだと8方向化で斜めのダッシュになり、生成の計画（真上へのダッシュ）と実物理が一致しなくなるため。計画・飛行スケジュール・計測表・閾値は変えていない。
- tests/dynamite_test.gd: 丸い穴を前提にした検査を長方形の穴に合わせて書き直した（掘る位置・方向を指定する `dig`、穴の外として確かめる点、地図の未探索の判定を「`explored_cells` に無いか」に変更）。床で止まる・横に当たると落ちる検査は、床・薄い足場・壁・天井に張り付く検査に変えた。被弾は「半径96pxの円」から「長方形と半径48pxの円」に合わせて配置を変えた。方向の決定、長方形の形、自機の上での下向きの穴の端から端までの一致を足した。

## 検査

test.cmd の42実行（新しい tests/dash_aim_test.gd を含む）を、APPDATA をプロジェクト内の .userdata にして1本ずつ直接実行した。計296,834件。40実行は失敗0・終了コード0・SCRIPT ERROR なし。

| 主な検査 | 検査数 | 結果 |
|---|---:|---|
| dash_aim_test（新規） | 56 | 成功 |
| dynamite_test | 627 | 成功（爆発1回の地形処理 0.393ms） |
| gravity_test | 87 | 成功 |
| ability_physics_test | 36 | 成功 |
| ability_generation_test | 860 | 成功 |
| impact_effect_test | 3,412 | 成功 |
| run_tests | 1,955 | 成功 |
| playthrough | 101 | 成功 |
| generation_test | 21,785 | 成功 |
| sector_test | 68,692 | 成功 |
| boss_arrow_test | 91 → 92 | 1件失敗、テストを直して成功（下記） |
| audio_test | 43,344 | 全体実行で1件失敗、単独の再実行で成功（下記） |

- boss_arrow_test の「boss defeat does not announce arrow unlock」: 通常敵20体を倒す途中で部屋が全滅し、Task 9C のダイナマイトの通知（「ダイナマイトは満杯です」、残り6秒）が残っていた。コミット済みの fc7def0（9D の変更を除いた状態）でも同じく失敗するので、9C からの問題。ボスを倒す前に「残っている通知はダイナマイトのものだけ」を確かめてから通知を消すようテストを直し（検査1件追加、ボスの撃破で通知を出さない検査は変更なし）、92件・失敗0を確認した。
- audio_test の「asset main-thread service/operation each <8ms」: 全42実行の中では8msを超えたが、単独で再実行すると43,344件すべて成功した。処理時間の検査なので、実行中の負荷による揺れと判断した。

爆発1回の時間は、4,096×512px の岩の中で11×3セル（33セル）を掘る dynamite_dig を1回測った値。衝突の分割・行の更新・縁と描画の更新予約を含み、音・ダメージ・地図画像・GPU描画は含まない。

実描画（非 headless、1280×720）でも録画し、8方向と方向転換、残像、射撃方向の矢印、床の上で跳んで下へ掘る穴・自機と反対の横へ掘る穴を目で確かめた。
