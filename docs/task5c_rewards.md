# Task 5C：誘導弾ストック・回復・復活

2026-10-26。Task 5B-2の区画ストリーミング上に追加。ボス移動・追加ボス・チュートリアルは対象外。

## 実装

- 自機は初期ストック0回・吸収0。吸収4回で1回分、通常敵の撃破で1回分、ガーディアンで2回分。上限5回。上限では吸収メーターも4までためて止め、発射後の次の吸収で変換する。キーを押すと1回分を消費して4発を同時発射する。0回なら発射しない。敵の8ゲージ・予告・発射は変更しない。
- 異色優先の画面内候補、巡回割当、対象撃破後の最少本数への再照準を維持。5Cでは照準印を次の1回分の最大4体だけにしていたが、4Aの仕様からの退行だった。5Dで「次の1回分」と「飛行中の自機誘導弾の追尾先」の和集合に修正し、検査も復元した。異色がいない場合の同色候補・候補不在時の前方発射は維持。HUDは5個の四角と吸収数・バー、取得時は頭上右側に「誘導弾 +1」等を表示する。
- ハートは専用の `(seed,区画座標,"hearts")` の乱数で0〜2個。通常空洞の到達グラフ上の立ち位置から選び、岩・箱、敵の体・巡回範囲・飛行レーンを避ける。開始・ガーディアンの空洞と地図には表示しない。ピンクのハート形が上下に揺れる。
- ハートはHP30、箱はHP6回復。最大HPを超えず、ハートは満タンでは取らない。箱の回復は自機の通常弾・誘導弾による破壊だけ。敵の爆発と一時的な設置壁の破壊では回復しない。共通の `heal` を通し、Task 5AのHPバーと実際に増えた数値を表示する。
- 消失した対象ごとに、永続ID・種別・元の配置・消失時刻・次の試行番号を `SectorStream.missing` へ保持する。45秒後を最初の機会とし、以後5秒ごとに25%。乱数はシード・ID・マイクロ秒へ丸めた消失時刻・試行番号から作る。グローバル乱数や生成順に依存しない。
- 視界を96px広げた矩形と対象の領域が交差する場合は復活を見送る。敵の領域は体と全巡回範囲、飛行敵は上下の揺れも含む。プレイヤー・敵の体・設置壁・地形との重なりも避ける。掘削で元の支持面を失った地上敵は戻さない。敵は元の位置、HP満タン・ゲージ0・画面に入ってからの待機から再開し、再撃破のスコア・撃破数・ストックも加算する。
- 区画解放中もゲーム内時刻で判定し、成功時は保存した箱の耐久・敵の撃破状態を更新する。ハートの消失記録も区画とは独立して残す。解放中の敵は、保存した位置・体の大きさでも重なりを調べる。生成ジョブが保存状態を扱う間は完成まで判定を保留し、完成後に未処理の機会を処理する。読み込み直した直後に視界内へ出現させない。復活した箱のセルも区画の解放対象へ登録する。
- 一時停止・設定・読み込み待ちではゲーム内時刻が進まない。削れた床とガーディアンは復活しない。再挑戦は新しいストリームを作り、破壊・収集・復活時刻・探索・ストック・撃破・スコアを初期化する。

## 範囲と未確認

5Dで既存の `builds/qa/rewards/verification_audit.json` と5Cの採用ログを照合し、変更前のソースを固定して全テストを再実行した。5C時点の件数・終了コードは同監査記録と一致する。5Dでの再実行結果は `task5d_bosses.md`。上記の照準印について、5Cの実装説明は実際の挙動に合っていたが4Aの維持要件に反していたため、ここに訂正した。過去の性能値は5C時点の計測として残す。

異色候補がいない場合の同色への誘導は既存規則を維持した。追加の安全条件として、掘削で元の支持面を失った地上敵は空中出現を避けて復活を見送る。それ以外の意図した仕様逸脱はない。復活の判定時間は一時停止を除くゲーム内時間で、実時間の待機や保存ファイルによる別起動への継続は対象外。
